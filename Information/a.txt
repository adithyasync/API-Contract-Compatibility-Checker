Initial Compatibility Rules:

                Rule	----------------------                         Initial expected classification
                Endpoint removed	----------                         Breaking
                Required request parameter added	--                 Breaking
                Required request field added	-------                Breaking
                Response field removed	                               Breaking
                Response field type changed	                           Potentially breaking
                Optional response field added	                       Usually compatible
                New optional query parameter added	                   Usually compatible
                HTTP response status removed	                       Depends on how clients use it
                Authentication requirements tightened	               Potentially breaking


Possible Cases:

                --> A valid OpenAPI file that describes a breaking change.

                --> A malformed YAML file that cannot be parsed.

                --> A syntactically valid OpenAPI file with an invalid or unresolved reference.

                --> A valid specification whose API is implemented incorrectly.
